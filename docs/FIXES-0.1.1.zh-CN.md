# 0.1.1：首发、GIF、聊天布局与导入路径修复

本轮按用户实测反馈修复。工坊现有条目为 **3833045408**，更新它，不创建第二个条目。服务器与客户端都需升级到 0.1.1，握手与网络频道使用协议 v2。

## 修改

- **首次发送慢**：去掉每块固定等待；握手成功后立即进入传输，取消误用握手时间带来的额外两秒等待。使用 32 块滑动窗口、每次更新最多 8 块、发送前带宽检查及失败回压。单连接最多 128 KiB/s，服务器所有连接共享 128 KiB/s 总出口，并非每名收件人各占一份总预算。
- **GIF 变静图**：旧导入器按 100ms 取样，可能把短小两帧 GIF 压成单帧。新版只在超过 48 帧时采样，保留短 GIF 多帧和延时（最低 20ms）。已被旧工具丢掉的帧无法从旧 ECP 恢复，需用新工具重新导入原 GIF。
- **动画绘制**：纹理更新移到游戏每帧 Draw 开始，先复制单帧到复用缓冲，再从零偏移上传；SpriteBatch 绘制期间不更新纹理。聊天、预览和头顶共用同一帧；可见资源轮询，每帧最多两次上传，服务器没有 GPU 工作。
- **错位/偏移**：替换原正文组件，图片放在原生姓名/时间行下方，不再额外追加到已经测量过的长正文之后。展开聊天、折叠提示与大厅分别处理。折叠提示显式保持标题高度，避免父容器递归缩放把图片推到框外；窄窗口和 UI 缩放时重新布局。
- **长串标识外露**：长串实际是内部资源哈希。原生测量文字前清空正文和已缓存的翻译正文；原生头顶文本气泡跳过表情标识。保留正常玩家名和时间，不显示文件名、哈希或额外的“表情”正文标签。消息内部元数据在处理后恢复，普通聊天不改。
- **导入器依赖所在盘**：新版导入器和游戏统一使用 `%LOCALAPPDATA%/Barotrauma/EmoteChat/Library`。EXE 可复制到任意磁盘，不依赖启动目录或游戏安装盘。兼容读取仍在旧模组 `Library` 的表情，新库优先。请使用随 0.1.1 发布的新 EXE；旧 EXE 的行为不会自动改变。

## 多人及服务器开销

未缓存且有权收件的玩家第一次必须收到图片数据；不会给频道之外的人额外广播。服务器只保留一份经过校验的压缩资源，不为每名收件人复制完整资源、不展开完整像素、不播放动画、不扫描图片文件。下载轮流分发，出口 128 KiB/s、入口 256 KiB/s，缓存 8 MiB、并行上传最多 8 个，后台验证继续串行约束。发送预算不足时不构造包，减少拥塞时的 GC。

客户端缓存最多 24 MiB；本次游戏进程内重连同一服务器保留已验证缓存，切换服务器清除，避免跨服务器混用。不把其他玩家的资源自动写盘。多人同时首次接收大图时会按总预算排队，人数越多首次完成越久；缓存命中后不再重复下载。

## 验证记录

- Python 导入/打包回归：10 项检查，包含短两帧 GIF、从不同目录启动的导入工具共享库、中文路径、格式与体积限制。
- C# 核心：55 项检查和 11,000 个随机/结构化畸形格式输入。
- 同一份 258154 字节资源，含丢包/重复/乱序的模拟：0ms RTT 上传约 2.76 秒，800ms RTT 约 12.70 秒；原 0.1.0 相应测试约 36.48/69.74 秒。是协议模拟，不是实际网络测速。
- 16 个无缓存收件人模拟：源端只上传一次，约 2.12 秒；全部收齐约 36.45 秒，总出口保持 128 KiB/s，服务器仅缓存一份压缩资产。
- 10,000 次带宽耗尽的服务端调度：没有构造不可发送的数据包，托管分配为零。不是整个游戏的分配/FPS 结论。
- 真实 1.13.5.0 程序集隔离检查：48 项。安装/卸载补丁、实际执行文本标识清理、实际原生 RectTransform/GUILayoutGroup 层级在 0.75/1/1.5/2 倍输入下检查展开行、窄窗口、折叠提示的边界。布局用合成标题尺寸，不加载游戏字体或场景。
- Windows Direct3D/WARP 测试：CI 执行真实纹理、SpriteBatch、头顶/聊天两处像素回读、绘制边界及导入 GIF 多帧纹理回读。以本版本成功 CI 为准。

仍需本地真实双客户端与具体模组组合复核；这里不启动用户的游戏或冒充硬件/全场景验收。发布包包含绑定现有工坊 ID 的更新状态，供本地登录 Steam 后更新。
