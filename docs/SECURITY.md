# 安全边界与资源预算

这是实现边界说明，不是第三方安全审计证明。攻击面包括恶意客户端、恶意或损坏的资源、乱序/重放分块、资源洪泛，以及本地导入的畸形图片。游戏服务器及 LuaCs/C# 模组本身具有较高权限，应仅从可信来源安装。本模组不沙箱化其他模组或不可信服务器。

## 不可信资源的处理

原始图片在本地独立工具中由固定版本 Pillow 解码。读取源文件的快照上限为 8 MiB，限制源尺寸和帧数，拒绝不支持的格式、文件符号链接与明显损坏的输入。该工具不是操作系统级沙箱，也不能证明第三方解码器不存在漏洞；不要导入来历不明的文件。独立工具不会由游戏自动启动。

工具将颜色转为预乘 alpha 的 RGBA，限制尺寸、帧数和时长，再写入 ECP1 文件。包中不含远程 URL、文件路径、脚本、文件名、外部调色板或任意元数据。游戏端不会把远端字节交给 PNG/GIF/JPEG/native 图片解码器。

ECP1 使用小端：`ECP1` 四字节、宽/高/帧数/保留位各 UInt16、每帧 UInt16 毫秒延迟，随后是 raw DEFLATE 压缩的 RGBA 帧。保留位必须为零，每帧延迟 20–10000ms，总时长 ≤10000ms。接收端先校验完整文件体积与 SHA-256，再检查头部，依据受限尺寸分配内存；实际解压必须恰好产出预期像素字节数。多余或缺失的解压数据被拒绝。SHA-256 用于内容标识与完整性，不代表作者身份或安全认证。

服务器仅用 8 KiB 流式缓冲验证像素长度，不为整段动画分配像素数组。客户端最多为单个资源分配 128×128×48×4 = 3 MiB 像素。后台解码由共享信号量串行调度，工作线程不接触游戏对象和 GPU；卸载后的结果不再发布到游戏。

## 协议与权限

使用 LuaCs 固定频道 `emotechat.pixels.v2` 和可靠投递。包体最大 810 字节；长度不正确时在解析前丢弃。握手协议版本为 2。客户端身份取自 LuaCs 提供的实际连接，不接受自报玩家 ID。资源名称是固定长度 SHA-256，不作为远端文件路径使用。

资源分块 ≤768 字节，32 块发送窗口。乱序块放入已分配的接收缓冲，窗口外的块丢弃，不另建分块队列；只有连续片段推进确认偏移，重复块不覆盖数据。发送者重试未确认区间，重复确认触发快速重传；180 秒超时。服务器最多接纳 8 个并行上传、64 个连接状态，每个连接最多记住最近 32 个已上传哈希。大小检查先于接收缓冲分配，数据验证成功后才进入可用缓存。

表情标识走原版聊天。服务器在原版 `SendDirectChatMessage` 已确定收件人的位置核对发送者资源所有权，并给予该收件人 60 秒请求许可。私聊不会额外广播；死亡/距离/无线电规则仍由原版执行。客户端仅请求原版聊天实际收到的完整标识，且只接受正在等待的资源。头顶气泡只用于普通/无线电消息，关联实际人物对象，不用于私聊、死亡频道或复用的实体 ID。

原版聊天反垃圾规则继续生效；官方客户端另有两秒发送冷却。修改过的客户端无法依靠这个本地冷却作为服务器安全屏障，服务器仍依赖原版聊天限流和模组传输限流。

## 可计量的上限

| 项目 | 限制 |
| --- | --- |
| 压缩资源 | 256 KiB / 项 |
| 单资源像素 | 128×128×48×4，最多 3 MiB |
| 每连接输入 | 192 KiB/s，32 KiB 突发，384 包/s、64 包突发 |
| 模组全局输入 | 256 KiB/s，64 KiB 突发；1024 包/s |
| 单连接输出数据调度 | 128 KiB/s，8 KiB 突发 |
| 模组全局输出 | 128 KiB/s，16 KiB 突发，包含应用层控制包预算 |
| 客户端缓存 | 24 MiB，32 项 |
| 服务器缓存 | 8 MiB，64 项 |
| 并行上传装配 | 服务器最多 8 个，每个 ≤256 KiB |
| 客户端 GPU 纹理 | 每项一张 ≤128×128 RGBA，最多约 2 MiB |
| 主线程上传 | 每次更新 ≤2 张完整纹理；不可见资源不刷新 |
| 头顶气泡 | 最多 16 个，每个显示约 6 秒 |

这些数值不是整个进程内存上限。任务、DEFLATE 内部缓冲、瞬时数组、UI、传输中被引用的已淘汰缓存项、游戏网络与图形驱动均有额外开销。可靠传输重传和底层协议头也不计入应用层字节预算。

远端资源仅驻留内存，不会自动写盘，不扫描磁盘、上传原图、执行命令或访问外部图片服务。切换服务器清除远端缓存；同一进程内重连同一服务器保留已验证缓存，卸载时撤回自身 Harmony 补丁、清理资源和回调。界面缩略图的本地加载队列最多 8 项、单工作任务。

## 实机发布前必测

真实双客户端、房主端、专用服；普通/无线电/死亡/私聊/屏蔽玩家；距离干扰；断线换服；其他聊天模组竞争补丁；窗口缩放/低分辨率/不同 DPI；动画透明与 GIF disposal；低带宽/高延迟/多人同时发送；长期缓存淘汰和显存清理。必须记录实测，不能用编译通过替代这些结果。

0.1.1 不在服务器引入 GPU 操作、磁盘图片扫描或完整像素数组。全局带宽不足时在构造数据包前停止调度，发送失败不推进传输偏移。完整像素和纹理仅在客户端；纹理在帧开始时上传，绘制期间不修改。


0.3.0 的收到图库只持有当前服务器最多 32 项标识/名称，复用原有内存缓存。只有用户主动点击保存或收藏，才将已验证的 ECP 规范化资源写入统一用户图库；不保存远端原文件/文件名，不额外下载。单后台任务再验证校验和、受限解压及固定哈希路径，拒绝链接目录/文件，受限读取并原子写入；128 项保存预算、16 KiB 收藏元数据预算。收藏不会自动上传或向服务器报告，取消收藏不删除图片。聊天昵称独立使用原生 SenderName 的纯文本标题，图片标识消费机制保持不变。
