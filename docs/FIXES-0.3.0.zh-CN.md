# 0.3.0：收到表情加入图库、收藏及昵称修复

0.2.0 的纯图片行省略了发送者标题。本版在展开聊天、折叠提示和大厅恢复独立昵称标题，头顶仍只显示图片。优先取原生游戏消息的 SenderName，无名称时使用关联玩家/人物名称；不从资源哈希、文件名或账号 ID 推导昵称。

昵称使用 RichString.Plain 绘制，去掉控制字符并限制异常超长名称；图片标识仍在原生聊天/Lua 聊天事件之前消费。昵称与图片独立布局，行高包含标题、间隔和图片，缩放/窄窗口时重新计算；折叠提示为标题预留宽度。

客户端对实际 1.13.5.0 引用编译通过，99 项原生接口、文本拦截、昵称与布局检查通过。新增昵称覆盖中文、空格、富文本符号、控制字符、长度上限；昵称与图片布局覆盖 0.75/1/1.5/2 倍缩放及窄聊天窗、折叠提示。Windows CI 继续检查双端编译、导入器、协议、GIF 软件 GPU 和打包。

没有修改服务端逻辑、网络协议、带宽预算或资源解码。客户端更新即可修复显示，与 0.2.0 服务端兼容。仍提供完整双端包，工坊只更新现有 3833045408。实际本地多人和工坊上传待本地执行。


## 收到与收藏

F8 打开「收到」，选中已接收的图片后点「加入图库」即可永久保存在自己的统一图库；点「收藏 / 取消收藏」会先保存，再写入本地收藏。取消收藏仅移除标记，不删除图片。「收藏」分类支持搜索及发送，卡片以星标提示。收藏和保存文件保留至重启后，GIF 保存原有完整规范化动画数据。

收到分类只保留当前服务器最近 32 个资源标识和发送者名称，复用原有受限内存缓存，不额外下载或自动写盘。缓存已过期的资源须由对方重新发送后再保存。保存仅在显式点击后由一个后台任务执行：再次校验 SHA-256 与格式、拒绝链接目录/目标文件、只使用规范哈希命名、原子写入。图库最多 128 项，单资源仍不超过 256 KiB；收藏文件有 16 KiB/128 项上限。重复资源不覆盖，损坏已有文件报错。

核心测试新增实际文件持久化、收藏重读/取消、重复保存、非法路径、损坏数据、偏好文件上限、图库容量和符号链接保护；共 72 核心检查（Windows 若没有符号链接权限会明确跳过对应两项）。昵称与图像布局 99 项原生检查。未改变服务端传输逻辑与协议 v2，兼容 0.2.0 服务端。
